# tetra_odom_calibration

웹 관제 관리자 화면 **바퀴 오도메트리 보정**이 쓰는 노드. 로봇을 천천히 직진·제자리 회전시키고, 출발 전과 멈춘 뒤의 라이다 스캔을
맞춰(ICP) 실제 이동량을 잰다. 오도메트리와의 비율이 바퀴 드라이버의 보정 배율이 된다.

| 배율 | 뜻 | 드라이버 파라미터 |
|---|---|---|
| 직진 | 실제 거리 / 오도메트리 거리 (바퀴 지름 오차, 타이어 마모) | `odom_linear_scale` |
| 회전 | 실제 회전 / 오도메트리 회전 (바퀴 간격 오차) | `odom_angular_scale` |

오도메트리(x, y, θ)는 구동보드가 보드 안의 바퀴 값으로 계산한다. 보드 파라미터 번호의 뜻을 적은 문서가 없어서 보드는 건드리지 않고,
`tetra_wheel_driver` 가 보드 오도메트리의 매 주기 이동량에 배율을 곱해 다시 적분한다 (`src/odom_scale.hpp`).
배율은 `~/.config/tetra/wheel_odom_scale.txt` 에 남고(드라이버가 씀) 0.8~1.2 만 받는다. 배율 1 이면 예전과 똑같이 보드 값을 그대로 낸다.

## 실행

API 가 화면을 열 때 `ros2 run tetra_odom_calibration calibrator --ros-args -p scan_topic:=<lidar_topic_name> -p http_port:=8092` 로 띄우고 떠날 때 끈다.
127.0.0.1 HTTP: `GET /status`, `POST /straight {distance}`, `/rotation {turns, direction: ccw|cw}`, `/stop`, `/apply {linear, angular}`, `/restore-default`, `/clear`.

## 안전

- 속도는 0.15 m/s, 0.4 rad/s 이고 목표 가까이에서 줄인다 (`motion_plan.py`). `cmd_vel_manual`(조그와 같은 입력)로 보낸다.
- 직진: 출발 전 폭 0.7 m 통로에 (거리 + 0.45 m) 이상 비어 있어야 하고, 가는 중 앞 0.45 m 안에 뭔가 들어오면 멈춘다. 회전: 둘레 0.45 m.
- 화면이 상태를 5초 넘게 묻지 않으면 바퀴를 세운다 (화면 닫힘·네트워크 끊김). 노드가 죽으면 드라이버의 명령 시간 초과(0.5 초)가 세운다.
- 이동·도킹·태스크·탐사·충전 중에는 API 가 시작을 거부한다.

## 측정

- 출발 전·도착 후 각각 스캔 3장을 base 좌표로 옮겨(라이다가 중심에서 떨어져 있으면 제자리 회전에도 움직인다) 첫 출발 스캔에 맞춘다. 가운데 값을 쓴다.
- 회전 오차 2% 면 두 바퀴에 14° 가 어긋나 ICP 가 엉뚱한 데 붙는다. 그래서 오도메트리 각도 ±20° 를 0.5° 간격으로 먼저 훑는다 (`motion_match._search_yaw`).
- 겹침 60% 미만·오차 3 cm 초과·비율 10% 넘게 다른 시험은 쓰지 않는다 (`evaluation.py`). 제안 = 지금 배율 × 받아들인 비율의 중앙값.
- 적용하면 지난 시험을 비운다. 예전 배율로 잰 비율이라 남기면 새 배율에 또 곱해진다.
